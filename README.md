# DataPulse

ELT-платформа, встроенная в Postgres: **прозрачный pgwire-прокси**
над вашим кластером. Клиент (psql, DataGrip, psycopg, …) подключается
к прокси как к обычному Postgres со своей учёткой — весь SQL
пробрасывается как есть, а команды DPL перехватываются и исполняются
движком под системной учёткой.

Состояние: итерация 4 — релей, весь DDL-скоуп (`datapulse`,
`dataset`, `build_spec`, `*_connection`, `comment on`, `test`),
`python`-блок и движок билдов: `build` / `attach` / `stop` / `fix`.

## Конфигурация (переменные среды)

| Переменная | Обязательна | Значение |
|---|---|---|
| `PG_HOST` | да | адрес родительского кластера Postgres |
| `PG_PORT` | нет (5432) | его порт |
| `PG_USER` | да | системная учётка движка (исполняет DPL) |
| `PG_PASSWORD` | да | её пароль |
| `DP_PORT` | да | порт прокси (слушает 0.0.0.0) |
| `DP_ENCRYPTION_KEY` | нет | ключ шифрования секретов (base64, 32 байта); не задан — генерируется случайный на время жизни процесса: секреты коннектов не переживут перезапуск |

Пароли пользователей прокси не видит и не хранит: аутентификация
сквозная, SCRAM-обмен идёт между клиентом и самим Postgres.

Системной учётке (`PG_USER`) нужен атрибут `CREATEROLE`: на каждый
билд создаётся временная учётка с урезанными правами.

## Запуск

Способ запуска — Docker; образ содержит только сервис (Postgres в
поставку не входит):

```
docker build -t datapulse .
docker run -d --name datapulse -p 8000:8000 \
  -e PG_HOST=... -e PG_USER=... -e PG_PASSWORD=... -e DP_PORT=8000 \
  datapulse
```

Если родительский Postgres крутится в докере на той же машине —
`PG_HOST=host.docker.internal`.

Подключение — любым Postgres-клиентом, имя БД и учётка — настоящие,
из родительского кластера:

```
psql "host=... port=8000 dbname=mydb user=alice"
```

## Команды DPL

- `create datapulse (схема_1, схема_2, …)` — установка в БД текущего
  подключения: схема метаданных `datapulse` + перечисленные схемы
  данных, одной транзакцией. Если любая из схем уже существует —
  ошибка. Запись в метаданные — только системной роли (гранты),
  чтение — открыто.
- `drop datapulse` — снос установки: схемы данных из объявленного
  списка и схема `datapulse`, cascade (со всеми данными).
- `create [or replace] dataset схема.имя (атрибут тип, …,
  primary key (атрибут, …))` — регистрация датасета в каталоге:
  новая версия метаданных (`datapulse.version` + `dataset` +
  `dataset_attr`). Схема — из объявленных при установке; `primary
  key` обязателен (фундамент SCD2). Типы: `text`, `integer`,
  `bigint`, `numeric[(точность[,масштаб])]`, `boolean`, `date`,
  `timestamp`, `timestamptz`. В схеме данных создаётся табличная
  функция датасета `схема.имя(build_id bigint default null)` с
  колонками: ключевые атрибуты, `build_id`, `end_build_id`,
  `is_active`, неключевые атрибуты — union all по основным таблицам
  живых спек (без спек тело пустое).
- `drop dataset схема.имя` — снятие датасета с каталога:
  tombstone-версия в метаданных (прежние версии остаются в журнале),
  функция датасета дропается. RESTRICT: живые свои спеки и чужие
  спеки-читатели — ошибка.
- `comment on datapulse is 'текст' | null` — описание установки:
  новая версия каталога; описание копируется в последующие версии
  (текущее — в последней строке `datapulse.version`).
- `comment on dataset схема.имя is 'текст' | null` — комментарий
  датасета: новая версия датасета с копией атрибутов; комментарий
  переживает `create or replace` и дублируется на функцию датасета
  (`comment on function`).
- `comment on attr схема.имя.атрибут is 'текст' | null` — комментарий
  атрибута датасета; при `create or replace dataset` комментарии
  атрибутов сохраняются сопоставлением по имени. Живёт только в
  метаданных: Postgres не комментирует колонки результата функций.
  `comment on` прочих объектов (table, column, …) — обычный Postgres,
  уходит релеем.
- `alter datapulse add схема` — новая схема данных: создаётся в БД
  (usage на public) и дополняет объявленный список установки; новая
  версия каталога.
- `create [or replace] build_spec схема.имя.номер (режим, …) with
  (parallel = N, chunk_attr = атрибут) [using коннекты | from
  датасеты] as python $$тело$$` — спека билда: режимы
  (`clear|dirty init|incr|sect|appd|skip mode имя`), опции,
  источники и инертное Python-тело. В схеме данных создаётся пара
  таблиц: основная SCD2 `имя_N` и интерфейсная `имя_N_$`; функция
  датасета пересобирается в union all по живым спекам (параметр
  `build_id` — срез «на момент билда»).
- `drop build_spec схема.имя.номер` — tombstone в метаданных;
  таблицы спеки удаляются физически (данные держатся актуальными,
  глубокий откат — только у метаданных); функция датасета
  пересобирается (последняя спека — откат на заглушку).
- `create [or replace] oracle_connection|postgres_connection имя with
  (поле = значение, …)` — коннект к источнику. Поля oracle:
  `host_name`, `port_num`, `service_name`, `user_name`, `password`;
  postgres: `host_name`, `port_num`, `database_name`, `user_name`,
  `password` — все обязательны, дефолтов нет. Секреты шифруются
  AES-256-GCM ключом `DP_ENCRYPTION_KEY` прямо в `param_json`
  (`{"enc": …}`); `or replace` может сменить класс коннекта. Имя
  `warehouse` зарезервировано: коннект на БД самой установки
  предоставляет платформа.
- `test имя_коннекта` — проверка коннекта реальным подключением к
  целевой базе (select 1); версию каталога не бампает.
- `python $$тело$$` — отладочный прогон инженерного Python-кода в
  процессе-ребёнке: в globals — фабрики всех живых коннектов
  (`with rbs() as v_rbs:`) и `warehouse` (коннект на БД установки);
  печать стримится клиенту NoticeResponse-ами, Ctrl+C (CancelRequest)
  убивает прогон. Команда названа `python`, а не `do` (имя донора):
  `do $$…$$` неотличим от анонимного блока Postgres, который
  прозрачный прокси обязан пробрасывать.
- `build('схема.имя', номер, 'режим')` — асинхронный запуск билда
  спеки: немедленно возвращает таблицу с `build_id`, исполнение не
  привязано к соединению клиента. Фазы: load — тело спеки в
  процессе-ребёнке под временной учёткой билда (в globals —
  `using`-коннекты, `warehouse` и параметры запуска `mode_code`,
  `from_build_id`, `to_build_id`, `previous_time`, `parallel_cnt`),
  comp — чанковый SCD2-перенос интерфейсной таблицы в основную по
  типу режима. Статусы и печать — общим потоком в
  `datapulse.build_log`. Незавершённый билд (включая неразобранный
  fail) блокирует следующий запуск той же спеки.
- `attach(build_id [, позиция])` — живой хвост журнала билда:
  строки `build_log` с позиции стримятся NoticeResponse-ами;
  завершается, когда билд перестал быть активным (done | fail |
  fix). Ctrl+C отцепляет зрителя — билд продолжает жить.
- `stop(build_id)` — асинхронная остановка: kill процесса-ребёнка и
  откат незакоммиченных чанков, финал `fail` в журнале. Осиротевший
  после жёсткой остановки сервера билд `stop` тоже переводит в fail.
- `fix(build_id)` — упавший билд разобран: финальная строка `fix`,
  дельты потребителей оттаивают, спека снова запускаема.

Каждая команда, меняющая каталог, пишет строку в `datapulse.version`:
кто (`user_code`), что (`command`), чем (`src` — текст запроса как
пришёл).

DPL исполняется вне транзакции пользователя (внутри открытой
транзакции — ошибка) и распознаётся только как единственный
стейтмент запроса.

## Осознанные ограничения итерации

- TLS нет с обеих сторон: на SSLRequest прокси отвечает `N`
  (клиенты с `sslmode=require` не подключатся); шифрование обеих
  ног — позже.
- Channel binding не работает через посредника: механизм
  `SCRAM-SHA-256-PLUS` вырезается из предложений бэкенда; клиенты с
  `channel_binding=require` не подключатся.
- DPL — только в simple-протоколе (psql); из extended (JDBC/psycopg
  по умолчанию) — честная ошибка. Перехват в extended — позже.
- Pipelining клиентских сообщений вокруг перехваченной команды не
  поддержан.

## Тесты

```
pip install "psycopg[binary]" cryptography oracledb pytest
pytest tests
```

Пакет импортируется из `src` без установки (tests/conftest.py).
E2E-тесты требуют живой Postgres: задайте `PG_HOST`, `PG_USER`,
`PG_PASSWORD` (и при необходимости `PG_PORT`) — без них они
скипаются. Прогон создаёт и сносит служебную БД `datapulse_e2e`.
